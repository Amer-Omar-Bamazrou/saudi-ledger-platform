# Functional gap closure — the register and the plan

**Status (2026-09-16): REGISTER ONLY — nothing below is implemented. Awaiting the owner's review.** Current state authority: [CLAUDE.md §2](../../CLAUDE.md).

Built from the seven-workflow audit (findings file, "THE SEVEN-WORKFLOW AUDIT"), the ERPNext comparison's triage addendum, the pilot package/runbook, the pre-pilot sanity walk, and a fresh read of `main` `0ac5570`: schema, services, repositories, `postJournalEntry`, the VAT/ZATCA pipeline, banking, reports, permissions, audit, the OpenAPI contract, the web routes and the test suite. Every "current behaviour" cell names the file that proves it. Nothing is invented; where the audit named a gap that the repository has since closed, it is listed under "already closed" so it is not re-opened.

**Two columns the owner asked for.** *Blocks* = "stops a Saudi SME from keeping compliant books at all" — YES means an SME with that fact pattern cannot record its position truthfully or meet a legal filing; COND = yes for SMEs with that fact pattern (assets, stock, non-resident suppliers, zero-rated supplies); NO = the books can be kept, the product is worse. *Days* = rough engineer-days at this repository's standard (red-before tests, invariants, docs, `pnpm run verify`, browser suite), one engineer. **The register is sorted by Blocks, then priority — not by module.**

**Statuses:** OPEN · OPEN-DECISION (needs an accounting-rule or scope decision first, §4) · BLOCKED-EXTERNAL · CLOSED (already fixed on main; listed so the audit's wording is not re-actioned).
